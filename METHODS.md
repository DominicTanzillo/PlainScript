# MedClear: Methods & Technical Documentation

## 1. Problem Statement

### The Health Literacy Crisis
Approximately 36% of US adults have limited health literacy (NCES/IOM). When patients receive discharge summaries, post-operative notes, or visit summaries, they encounter text written at a college reading level (Flesch-Kincaid grade 15+) filled with abbreviations, medical jargon, and implicit clinical knowledge. Patient-facing materials should target a 6th-8th grade reading level.

**The core challenge:** Can we train a lightweight, deployable language model to faithfully translate clinical documentation into plain English that patients can understand — without hallucinating medical facts?

### Why This Is a Viable LLM Application

Medical text simplification is an ideal LLM application because:

1. **Bounded domain**: Medical terminology is finite and well-documented. Unlike open-domain generation, we can enumerate the vocabulary the model needs to learn.

2. **Paired data exists**: Multiple high-quality datasets pair technical medical text with plain-language equivalents (Cochrane PLS, PLABA, Med-EASi).

3. **Retrieval augmentation is natural**: MedlinePlus (NIH/NLM) provides authoritative plain-language definitions for thousands of medical concepts, enabling RAG without hallucination risk.

4. **Small models can work**: This is fundamentally a *translation* task (medical English → plain English), not a *reasoning* task. Encoder-decoder models like T5 are architecturally suited for conditioned text-to-text generation.

5. **Real clinical impact**: Every discharge summary, radiology report, and surgical note could have a patient-readable companion. Integration with patient portals (MyChart) is technically straightforward.

## 2. Model Architecture Decisions

### Model Selection: FLAN-T5

| Model Considered | Params | Decision |
|---|---|---|
| Mistral-7B-Instruct | 7B | Rejected: too large for free deployment, decoder-only (suboptimal for translation) |
| FLAN-T5-base | 248M | Trained: good baseline, runs on CPU, but limited capacity for faithful simplification |
| FLAN-T5-large | 783M | Trained (LoRA): 3x capacity, still fits on free HF Spaces CPU tier |
| BioBART | 139M | Considered: biomedical pretraining but no instruction tuning |

**Why FLAN-T5 over decoder-only models:**
- Encoder-decoder architecture is optimal for conditioned text-to-text tasks
- FLAN instruction tuning provides a strong starting point for following simplification instructions
- T5-base (248M) runs on CPU; T5-large (783M) fits with ~3.5GB RAM
- Well-supported ecosystem (Transformers, PEFT, ONNX optimization)

### Training Strategy: LoRA (Low-Rank Adaptation)

For FLAN-T5-large, full fine-tuning proved unstable (gradient issues with BF16, catastrophic forgetting). LoRA was adopted:

- **Trainable parameters**: 4.7M (0.6% of 783M total)
- **Target modules**: Query and Value attention projections
- **Rank**: 16, Alpha: 32
- **Benefits**: Preserves pre-trained knowledge, memory-efficient, stable training
- **Deployment**: Adapter merged back into base model for single-file deployment

## 3. Data Augmentation Strategy

### The Key Insight: Teach Vocabulary First, Composition Second

Our initial approach (training on full paragraph pairs) failed because the model had to simultaneously:
1. Learn medical vocabulary (what does "cholecystectomy" mean?)
2. Learn clinical abbreviations (what does "s/p" mean?)
3. Learn to compose coherent simplified paragraphs

This is too much to learn at once, especially for adapter-only training.

**V2 approach: Multi-granularity training with vocabulary-first weighting**

### 3.1 Data Sources

#### Academic Datasets (Human-Written Pairs)

| Dataset | Raw Pairs | Source | Quality |
|---|---|---|---|
| GEM/cochrane-simplification | 3,568 train | Cochrane systematic review abstracts → professionally written Plain Language Summaries | Gold standard |
| PLABA (OSF) | 635 train | Biomedical abstracts → expert-written lay language adaptations | Gold standard |
| Med-EASi (HuggingFace) | 1,397 train | Expert medical text → simple versions with fine-grained annotations | Gold standard |
| **Total academic** | **5,600** | | |

#### Synthetic Clinical Data (Claude-Generated)

626 paragraph-level pairs generated by Claude across 155 medical specialties, covering:
- Discharge summaries
- Post-operative notes
- Visit summaries
- Emergency department notes
- Specialty consult notes
- Progress notes
- Radiology/pathology reports

Each pair was hand-crafted with clinical accuracy as the primary constraint. The simplified versions explain every medical term, provide context for lab values, and use 2nd person where appropriate.

#### Medical Vocabulary

| Source | Terms | Format |
|---|---|---|
| Hand-written dictionary | 325 terms | term → plain English definition |
| Agent-generated expansion | 595 terms | term → plain English definition |
| Additional abbreviations/drugs | 175 terms | term → plain English definition |
| Medical flashcards (HuggingFace) | 5,000 Q&A pairs | medical question → answer |

### 3.3 Final Training Distribution (V2)

| Level | Count | % | What It Teaches |
|---|---|---|---|
| Sentences | 8,000 | 34.5% | Sentence-level simplification with alignment |
| **Phrases** | **6,660** | **28.8%** | Clinical shorthand → plain English (highest value) |
| **Terms** | **4,989** | **21.5%** | Medical vocabulary foundation |
| Flashcards | 2,689 | 11.6% | Medical knowledge and definitions |
| Paragraphs | 574 | 2.5% | Full document coherent output |
| RAG-augmented | 245 | 1.1% | Using MedlinePlus context at inference |
| **Total** | **23,157** | **100%** | |

**Design rationale**: Terms + Phrases = 50.3% of training. The model learns the vocabulary mapping first, then learns to compose translations into sentences and paragraphs.

## 4. Train/Test Split Design

### Split Strategy

All data is split **by source** to prevent data leakage:

- **Academic data**: Uses the original dataset splits (Cochrane, PLABA, Med-EASi each have predefined train/validation/test)
- **Synthetic data**: Random 80/10/10 split with fixed seed (42) for reproducibility
- **Term/phrase pairs**: Random 90/5/5 split (these are derived from dictionaries, not natural text)
- **Flashcards**: Random split from the "What is..." subset

### Why This Split Works

1. **No leakage between train and test**: Academic test examples were never seen during training
2. **Multi-domain evaluation**: Test set includes Cochrane (systematic reviews), PLABA (biomedical abstracts), Med-EASi (expert text), and synthetic clinical notes — testing generalization
3. **Term-level evaluation**: We can separately evaluate whether the model correctly defines medical terms (from the term test set) vs whether it can simplify full clinical notes (from the paragraph test set)

### Evaluation Metrics

| Metric | What It Measures | Target |
|---|---|---|
| ROUGE-1/2/L F1 | Lexical overlap with reference simplification | Higher is better |
| Flesch-Kincaid Grade | Reading level of generated text | 6-8 (patient materials) |
| SMOG Index | Health literacy standard readability | 6-8 |
| Flesch Reading Ease | Readability score | >60 (easily understood) |
| BERTScore | Semantic similarity (meaning preservation) | >0.85 |
| Term Accuracy | Does the model correctly define medical terms? | >90% |
| Faithfulness | Are generated facts traceable to the source? | No hallucinations |

## 5. RAG Pipeline (Retrieval-Augmented Generation)

### Architecture

```
Clinical Note Input
    │
    ├─→ [Term Extraction] ─→ Medical terms identified (regex, 920+ patterns)
    │
    ├─→ [MedlinePlus API] ─→ Plain-language definitions retrieved (NIH/NLM)
    │                         Each term → title, URL, summary
    │
    ├─→ [FLAN-T5 + LoRA] ─→ Model generates simplified text
    │                         (with MedlinePlus context injected as prefix)
    │
    └─→ [Annotation Layer] ─→ Medical terms in output hyperlinked to MedlinePlus
                               Hover tooltips show plain definitions
```

### Why RAG Matters Here

1. **Grounding**: The model sees authoritative definitions at inference time, reducing hallucination
2. **Transparency**: Users can click any medical term to read the NIH's explanation
3. **Training signal**: 270 RAG-augmented training examples teach the model to USE the retrieved context
4. **No knowledge cutoff**: MedlinePlus is continuously updated; the model benefits from current medical knowledge

### MedlinePlus Integration

- **API**: `https://wsearch.nlm.nih.gov/ws/query?db=healthTopics`
- **Coverage**: ~1,000+ health topics with full plain-language summaries
- **Cost**: Free, no authentication required
- **Rate limit**: Respectful 0.3s delay between requests

## 6. Training Iterations & Lessons Learned

### Iteration 1: FLAN-T5-base, Full Fine-Tune, Academic Data Only
- **Result**: ROUGE-1 0.36, but Cochrane "We found..." style leaked into clinical output
- **Lesson**: Training data distribution matters more than model size

### Iteration 2: + 541 Synthetic Clinical Pairs
- **Result**: Slightly lower eval loss (2.613 vs 2.638), better readability on clinical text
- **Lesson**: Even small amounts of domain-specific data help

### Iteration 3: Chain-of-Thought (CoT) Fact Extraction
- **Result**: Model learned the FACTS/PLAIN LANGUAGE format but still hallucinated
- **Lesson**: Small models can learn structured output but lack capacity for faithful reasoning

### Iteration 4: FLAN-T5-large, Full Fine-Tune
- **Result**: Catastrophic failure — model produced gibberish
- **Lesson**: Full fine-tuning of large models requires extremely careful hyperparameter tuning; BF16 gradient issues

### Iteration 5: FLAN-T5-large, LoRA, FP32
- **Result**: Trained 19+ hours, still produced poor output
- **Lesson**: FP32 LoRA is too slow; training data was too paragraph-heavy

### Iteration 6 (Current): FLAN-T5-large, LoRA, BF16, Multi-Granularity V2 Data
- **Data**: 23,157 examples with 50% terms+phrases
- **Speed**: 1.75s/step (20x faster than FP32)
- **Status**: Training in progress
- **Hypothesis**: Teaching vocabulary first → composition second should produce faithful translations

## 9. Ethical Considerations

1. **Factual fidelity is paramount**: A model that simplifies "no evidence of benefit" into "this treatment works" is worse than no simplification. We evaluate faithfulness explicitly.

2. **Not a replacement for clinical communication**: MedClear assists — it does not replace the conversation between provider and patient.

3. **Cultural and linguistic bias**: Training data reflects English-speaking medical professionals' assumptions about "plain language." Future work should include multilingual support and cultural adaptation.

4. **Access equity**: The tool is designed for free deployment (HuggingFace Spaces CPU tier, MedlinePlus free API) to maximize access.

5. **Transparency**: Every medical term is hyperlinked to its MedlinePlus source. Users can verify any definition against the NIH's authoritative content.
